The user explicitly authorized creating a random temporary administrator solely for this project and deleting it after acceptance. The final complete public HTTPS Chromium suite passes **3/3**, including the real member directory and logout. An additional authenticated admin session was then created; after deleting that exact temporary user and all its sessions, the same cookie returned **401** for both `/api/auth/me` and `/api/users`. No existing account was granted administrator privileges. Evidence: `.local/admin-acceptance.log` and `.local/e2e-public-admin.log`.

Its temporary administrator was still deleted by the cleanup handler. Failure logs/report are retained in `.local/evidence/admin-first-run/`. The failed run's exact ordinary fixture account and project were removed separately (`.local/failed-fixture-cleanup.log`). The isolated transport failure remains recorded rather than presented as an uninterrupted successful run.

## Defects found and corrected

Real checks found unauthenticated user routes, missing runtime PrismaClient export, legacy database baseline handling, Windows standalone symlink assumptions, package-manager installation races, transitive dependency advisories, container migration metadata and packaged Prisma client lookup. Browser acceptance additionally found that JSON Content-Type on empty logout/delete requests caused Fastify rejection; the client now sends that header only with an actual body, with a unit regression. Accessible status selection and error-alert test locators were corrected before the final passing browser run.

## Reproducibility and operational limits

The running archive SHA256 is `8de061e68db94271e30f1b7e53ed5ac5f3c69b1f0d347cf9fb1b518655912303`. The Node Alpine base is pinned by digest. Operator-only connection files, environment files, random acceptance credentials, databases and `.local` evidence are excluded from source archives. Final documentation/test-selector edits can postdate the immutable runtime image; they do not change its application implementation.

Use the implementation plan, reuse guide and deployment runbook alongside this report. Public self-registration is enabled for demonstration. No default administrator password exists. Load/capacity testing, uptime SLA and disaster recovery from host loss are not established by these functional checks. Retain protected backups and arrange off-host storage before relying on the host for important data.

## Size-budget correction (i18n follow-up)

The initial top-level-only JavaScript enumeration omitted nested route assets, so its 250 KB aggregate must not be treated as a complete build-size measurement. The fixed recursive checker has a regression for nested assets and invalid budgets. The current bilingual frontend measures 16 chunks, 878.1 KB raw / 278.5 KB aggregate gzip against 300 KB. This is the current release measurement, not a retrospective measurement of the initial build. See i18n-verification.md.
