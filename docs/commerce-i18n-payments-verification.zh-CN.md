# 多语言与支付增量执行记录

日期：2026-10-18。用户在开发备忘录后明确“开始吧”。本轮实施 MEM-I18N-01 与 MEM-PAY-01 的可开发部分，其他平台开发目标不变。

## 实现范围

- 顾客商城英语、简体中文、法语、西班牙语消息目录，含错误、插值、复数、可访问性标签、样例商品译文、金额/日期格式。
- 语言偏好使用既有 cookie；服务器确定语言，客户端切换触发服务器刷新，保留同一路径/查询及现有会话。语言不改变 SKU、价格币种、库存或权限。
- 翻译 JSON 由服务器读取，仅将当前语言提供给客户端，避免一次加载全部语言的 JavaScript。样例商品译文按 SKU、字段和原始文本精确匹配；不自动改写商家或买家内容。缺失译文回退原文。
- 商家端与平台端尚未完成，不因为顾客端四语言而标记三端已验收。新增邮件/通知和真实商品翻译审核仍需对应模块实现。本次译文用于预览商城，不表示经营政策已获法律审核。
- 建立银行卡、PayPal、Apple Pay、Google Pay、微信支付、支付宝六种能力的默认关闭门禁，分别核验产品批准、凭据、服务商沙盒、订单账本、平台结算、市场/币种及真实资金验收。
- 实现 sandbox-only PayPal 协议适配器：OAuth、创建/查询/扣款/部分退款、幂等请求头和服务商回调验签；校验本方商户、业务订单、金额、币种、扣款完成状态及批准跳转地址。没有 live 主机开关，不自动读取生产凭据。
- 适配器尚未挂接现有订单路由或数据库。现有订单缺币种/支付尝试账本，且交易可靠性修复尚未验收，不能直接调用外部收单。微信/支付宝、银行卡及其他钱包未选择实际服务商，协议接入保持待办，不制造 SDK 空壳或付款按钮。

## 接通外部支付前的剩余工作

先明确并取得实际主体可用的收单/平台产品及商户号；验证统一付款拆子单的结算资格；补齐不可变报价/币种、PaymentAttempt、金额分摊、webhook inbox 去重、订单状态竞争与事务/Outbox、退款账本及对账。服务端从已授权订单读取金额与归属，不能信任客户端传入的 purchaseId、captureId、商家或金额。

之后配置服务商沙盒，由实际账号执行购买者批准、扣款、退款、重复/乱序回调、超时查询及对账；核对正确收款方和账本后，再走独立的生产资格与受控真实资金验收。仅有签名通过、跳转成功或 HTTP 200 均不能直接确认已支付。

参考：[PayPal Orders v2](https://developer.paypal.com/api/orders/v2)、[OAuth](https://developer.paypal.com/api/rest/authentication/)、[webhook 验证](https://developer.paypal.com/api/rest/webhooks/rest/)。本文对应 postback 验证真实应用事件，不能以 PayPal 模拟 webhook 工具事件代替真实应用签名流程。
